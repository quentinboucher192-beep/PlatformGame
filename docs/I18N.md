# Langues du jeu (français / anglais)

Le jeu s'affiche **en français ou en anglais**. Le français reste la langue source : tous les
textes sont écrits en français dans le code et dans les données ; l'anglais vient d'un
dictionnaire, `data/i18n/en.json` (français → anglais), appliqué **au moment de l'affichage**.
La langue ne touche jamais la simulation, les replays, les empreintes des niveaux ni les
classements.

## Choisir la langue

* **Installateur Windows** : la première fenêtre de l'installateur demande la langue
  (français ou anglais, présélectionnée d'après la langue de Windows). L'installateur
  s'affiche dans cette langue (licence comprise : `installer/license_fr.txt`,
  `installer/license_en.txt`) et écrit le choix dans `language.ini`, à côté de l'exécutable :

  ```ini
  [Language]
  Language=english
  ```

  Au lancement, le jeu lit ce fichier (`applyInstallerLanguage`, `saves/Settings.cpp`) et
  l'applique **s'il est nouveau** : premier lancement, ou jeu réinstallé dans une autre
  langue. Le choix est alors gardé dans les paramètres (`saves/settings.json`, bloc
  `"language"`). Un fichier plutôt qu'une clé de registre : rien à lire dans le registre,
  le même code sous Windows et Linux, et le fichier disparaît avec la désinstallation.
* **Dans le jeu** : *Paramètres › Jeu › « Langue / Language »* (en tête de l'onglet, nommé
  dans les deux langues). Le changement est **immédiat** : tous les textes sont traduits au
  moment où ils sont dessinés, il n'y a rien à recharger. Un message le confirme
  (« Langue : anglais, appliquée immédiatement. »).
* **Ligne de commande** : `--lang en` ou `--lang fr` (captures d'écran, tests).

Sans `language.ini` ni réglage (version portable, Linux), le jeu est en français.

## Comment ça marche

Un seul point d'accroche : le moteur de texte (`engine/rendering/Text.cpp`). `measure`,
`draw`, `drawWrapped` et `measureWrapped` passent d'abord le texte par
`i18n::display()` (`engine/core/I18n.h`). Tout ce qui s'affiche — boutons, onglets,
étiquettes, HUD, messages du monde, données des niveaux, ennemis, succès, actualités,
messages du serveur — est donc traduit, **et la mesure utilise exactement le même texte que
le dessin** : les calculs de place (`UIContext::fitFont`, `labelWrapped`, mesures des
écrans) restent justes dans les deux langues.

Recherche d'un texte (`i18n::Dictionary`) :

1. **texte exact** (`"Jouer"` → `"Play"`) ;
2. **modèle à emplacements** : `"{0} vaincu sans dégât !"` → `"{0} defeated without
   taking damage!"`. Les parties insérées sont traduites à leur tour
   (« Sentinelle Prime vaincu sans dégât ! » → « Prime Sentinel defeated without taking
   damage! ») ; les emplacements peuvent changer d'ordre (`"{1} sur {0}"` → `"{0} out of
   {1}"`) ; un mot peut suivre le nombre d'un emplacement : `"{0} {0|level|levels}"`
   (1 → *level*, 0 ou 2 → *levels*) ;
3. **parties** d'un texte : lignes, morceaux séparés par « · », « — », « : »…, signes
   autour d'un texte connu (« • Jouer : » → « • Play: »), texte en capitales
   (« PARAMÈTRES » → « SETTINGS »), première lettre changée ;
4. sinon : le texte reste **en français** (jamais vide).

Les nombres sont écrits à l'anglaise dans les textes sans mots et dans les parties
insérées : « 2,45 » → « 2.45 », « 12 345 » → « 12,345 », « 45 % » → « 45% ».

Les résultats sont gardés en cache (deux générations de 4 096 textes, vidées entre deux
images) : une recherche par texte affiché, puis une seule recherche dans une table de
hachage par image ; les textes sans lettre (chronomètres, compteurs) ne sont même pas
recherchés. Aucun coût mesurable par image.

**Textes des joueurs** : ce qu'un joueur a écrit n'est jamais traduit — texte en cours de
saisie (`UIContext::textField`), commentaires, messages des discussions. Le code qui
affiche un tel texte l'entoure de `i18n::Verbatim` :

```cpp
{
    i18n::Verbatim playerWords;  // affiché tel que son auteur l'a écrit
    ui.labelWrapped(jstr(comment, "body"), pos, width, 16);
}
```

**Texte raccourci** : `UIContext::elide` traduit d'abord, puis raccourcit le texte
traduit (il rend le texte français d'origine quand il tient, traduit au dessin). Un code qui
découpe lui-même un texte avant de l'afficher doit faire de même : `i18n::tr(texte)` puis
découpe, et `i18n::keep(morceau)` pour que le morceau soit dessiné tel quel. On ne redonne
jamais au moteur un texte déjà traduit : on lui donne le texte français (« Explorer » est un
mot français qui se traduit *Explore*, et aussi la traduction d'« Explorateur »).

## Ajouter ou mettre à jour des traductions

Après avoir ajouté des textes (nouvel écran, nouveaux niveaux, boss, pouvoirs…) :

```
python3 tools/i18n/extract.py                    # catalogue + rapport des textes non traduits
python3 tools/i18n/extract.py --todo todo.json   # les textes à traduire, valeurs vides
#   … remplir les valeurs anglaises de todo.json …
python3 tools/i18n/extract.py --merge todo.json  # les ajoute à data/i18n/en.json
ctest --test-dir build                            # test_i18n : rien ne manque
```

`extract.py` relit le code (`ui/`, `game/`, `engine/`, `editors/`, `packaging/`,
`saves/`, `main.cpp`), les données (`data/` : niveaux, planètes, ennemis et boss, pouvoirs,
succès, actualités, avatars et pays — dont le nom anglais `name_en` est repris tel quel —,
conditions d'utilisation, paragraphe par paragraphe) et les messages du serveur
(`server/src`, traduits côté jeu : le serveur ne change pas). Il écrit
`tools/i18n/catalog.json` (à ne pas éditer). Les textes composés deviennent des modèles :

| Code | Modèle extrait |
|---|---|
| `"Niveau " + std::to_string(n)` | `Niveau {0}` |
| `std::format("{} fichiers", n)` | `{0} fichiers` |
| `snprintf(buf, n, "%d morts", k)` | `{0} morts` |
| `"Voir les " + x + (n > 1 ? " réponses" : " réponse")` | `Voir les {0} réponses`, `Voir les {0} réponse` |

Règles du dictionnaire (vérifiées par `tests/test_i18n.cpp`) :

* chaque texte du catalogue a une traduction non vide ;
* une traduction reprend **les mêmes emplacements** que son modèle (`{0}`, `{1}`…, dans
  l'ordre voulu) ;
* le pluriel anglais suit le nombre : le français met le singulier à 0 et 1
  (« 0 niveau créé »), l'anglais `{0} {0|level|levels} created` donne « 0 levels created » ;
* typographie anglaise : pas d'espace avant « : ! ? », guillemets droits `"…"`, nombres
  avec point décimal.

Terminologie suivie : *Dash*, *Charged Shot*, *Energy Wave*, *Shield*, *Triple Jump*,
*Glider*, *Grapple*, *Seismic Slam*, *Short Teleport*, *Impulse*, *Time Slow*, *Plasma
Bomb*, *Magnet*, *Air Dash* ; éclats → *shards*, reliques → *relics*, point de sauvegarde →
*checkpoint*, embuscade → *ambush*, épreuve → *trial*, gardien → *guardian*, écho → *echo*,
station de pouvoirs → *power station*, mode concentré → *focus mode*, entraînement →
*practice*, course à la vérification → *verification race*, succès → *achievements*,
fantômes → *ghosts*. Les noms de planètes (Sylvanox, Glacior, Pyralis) ne changent pas ;
le Noyau stellaire devient *Stellar Core*, les boss gardent leur nom propre (*Cryowyrm*,
*Magmaroth*, *Ignivore*, *Thornwarden*) ou prennent un nom anglais cohérent (*Prime
Sentinel*, *Spore Queen*, *Frost Hydra*, *Glaciarch*, *Astrarch*…).

Ce qui ne doit pas être traduit (clé JSON, en-tête HTTP, nom de fichier…) et que
l'extracteur aurait pris pour un texte va dans `tools/i18n/ignore.txt`.

**Trouver un texte resté en français** : lancer le jeu en anglais avec la variable
`COSMIC_I18N_MISSING=<fichier>` : chaque texte affiché sans traduction complète y est
ajouté (une ligne JSON par texte).

```
COSMIC_I18N_MISSING=/tmp/missing.jsonl ./build/bin/CosmicPlatformer --lang en
```

## Ajouter une langue

`Language` (`engine/core/I18n.h`) liste les langues ; une nouvelle langue demande son
dictionnaire `data/i18n/<code>.json` (même format qu'`en.json`), son entrée dans
`i18n::code`, `nativeName`, `parse` et `dictionary`, une option dans le réglage
« Langue / Language » (`ui/screens/SettingsScene.cpp`) et une langue de plus dans
`[Languages]` de `installer/CosmicPlatformer.iss` (avec sa licence et ses `CustomMessages`).
